# Edit a post

> **Status:** In progress — fill per “part” of a post; add screenshots per section  
> **Who:** Post **author** and **contributors**  
> **Where:** Open the post → edit actions for each area

A post has several parts. You usually edit one area at a time (title & details, schedule, media, people, attendance, and so on).

## Before you start

- You must be the **author** or listed as a **contributor** on that post  
- Use the **web app** when making larger edits  

## Open the post for editing

1. Find the post on the **bulletin** (or via **My Posts** if you use that).  
2. Open the post.  
3. Use the edit / actions menu for the part you want to change.

## Parts of a post

Work through whichever sections apply. Add a screenshot under each heading as you document them.

### Title & details

1. Open **title / details** (or equivalent).  
2. Update the title, about text, and related fields. If people are already marked as attended, **Add who attended** fills the title with shuffled shortened names (for example John D.) and `+N` when every name will not fit.  
3. Save.  

### Schedule & roles

In the edit menu, **Schedule** holds add, reorder, and apply a preset.

1. Open the **Schedule** tab on the post (day timeline with overlapping items side by side).  
2. Add or change roles / assignments, or open **Arrange schedule** to drag items to new times (cascade or parallel mode). On the Schedule tab, tap an empty time to add an item that starts then. Press and hold an item to open its editor. Adding into a **free slot** keeps other times; overlapping a timed item asks whether to **keep times** (run together) or push later items. After a new item is saved, you can start the next one at that finish time. Changing the event **start time** (date & location) asks whether the whole schedule should **move with the start** or **keep current times**.  
3. Save.  

See [Reading the schedule](../../events-and-bulletin.md#reading-the-schedule) and [Rearranging the running order](../../events-and-bulletin.md#rearranging-the-running-order) for how the timeline works.

### Media

1. Open **media**.  
2. Add, reorder, or replace images and video. In **Key media**, use **Earlier**, **Later**, and **Make cover** (on a phone you can also drag the handle). The first image is the cover on the post card. **Post media** uses the same arrows, and a drag handle on a phone; that order is the gallery on the Media tab. A new image or video is marked as key media while fewer than four are set. **Choose from this month** lists the loose photos in a shared folder, newest first (the date Google Drive shows as last modified). The photos open as large tiles. **Show file names** switches to a list with each name and date. It opens on **Cell Groups** when the post already belongs to a cell group, and on **Services** otherwise. You can still switch group, then this month or last month. Nothing is selected until you pick the photos. Photos kept inside an event folder are not in that list — use **Bulk add from a folder**, paste that event folder’s link, and pick the files (also newest first). **Add image** or **Add video** is for a single link, and pasting a link checks it straight away. An area admin sets those folders from Personal → **Admin Tools** → **Shared media folders**. Starting a new month on a group keeps only that group’s two folders; anything older stays in Google Drive but is no longer offered in the app.  
3. Save.  

### People on the post

1. Open **people** / contributors.  
2. Add contributors who should be able to edit.  
3. Save.  

### Interest & attendance

1. Open the **People** tab on the post.  
2. Manage **expected** people and **attendance** (author and **contributors** can edit). A long list folds on a phone at nine people, and at about eighteen on a wide screen; **+ more** opens it.  
3. If the post is linked to a **cell group**, use **Fill from cell group** or **Add from cell group** (in the picker) to seed expected attendees when helpful.  
4. See who marked **interest** (“follow updates”) if needed.  
5. Tap **Save** on the post (same as other edits) and add a short **update log** (bookmarkers can be notified).  

Interest (“Mark interest”) saves immediately for the signed-in person; staff attendance changes wait for **Save**.

### Related posts

1. Leaders open **Related posts** in the edit menu, then create a **child** under this post, a **sibling** when this post already has a parent, or several at once. A **period parent** is set on **Title & details**, or while creating the post.  
2. Readers see links on the post’s **Related** tab.  

### Notify / broadcast

1. When the post is ready, use **broadcast** (or notify) if you want a push to people who opted into **All {location} updates** for that post’s location.  
2. Confirm the audience before sending (for example **All Belfast updates**).  
3. You can also notify people already on **programme roles** when creating the post, if that option is turned on.

More detail: [Notifications](../../notifications.md). Terms: [Key concepts](../../key-concepts.md).
